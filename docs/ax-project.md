# 내 업무를 AI 과업으로 정의하기

내 업무를 **'AI로 풀 과업'**으로 정의하는 도구를 모았습니다 — AX(AI 전환) 문제 정의 캔버스 · 과업 선정 3기준 · 페르소나 카드 · 옆 사람 검증. 따로 시간을 떼지 않습니다. 1일차 [현안 정의서의 '내 업무라면' 칸](day1/lab-b.md#b2-issue)과 조별 토론에서 한 번 써 보고, 5–6일차 **개인 도입 기획서**의 1–3장(요약 · 현황 · 문제 정의와 목표 KPI)을 쓸 때 꺼내 씁니다 → [기획서 11장](day6/submit.md#proposal).

    내 저장소가 공개이기 때문입니다. 자사 숫자는 [익명화 체크리스트](setup.md#byod)를 통과한 값만, 개인 기획서의 비공개 폼으로 냅니다.

!!! quote "AI 도입은 구매가 아니라 과업 선정이다"

    도구를 고르기 전에 **어떤 일을, 어떤 데이터로, 무엇으로 성공을 재는가**를 먼저 정합니다. AI 프로젝트 실패의 주원인으로 꼽히는 것도 도구가 아니라 **문제 정의를 잘못 이해한 것과 데이터 부족**입니다(RAND 2024).

## AX 문제 정의 캔버스 7칸 {#canvas}

아래 표를 메모장 · 워드에 옮겨 씁니다([1일차 현안 정의서](day1/lab-b.md#b2-issue)와 함께 보면 좋습니다).

| 칸 | 이름 | 무엇을 쓰나 | 좋은 예 / 아쉬운 예 |
|---|---|---|---|
| 1 | **업무** | 누가 · 무엇을 | "채권 담당자가 매주 연체 바이어 목록을 만든다" / "채권 관리" |
| 2 | **현재 방식** | 시간 · 빈도 | "엑셀 3개를 합쳐 주 1회, 2시간" / "수작업" |
| 3 | **불편 · 위험** | 무엇을 놓치면 비싼가 | "연체를 늦게 알아, 이미 연체 중인 바이어에 또 선적한다 → 못 받을 돈이 커진다" / "불편하다" |
| 4 | **데이터** | 무엇이 · 어디에 · 민감도 | "ERP 미수금 원장(사내 서버, 거래처명 포함 → 익명화 필요)" / "회사 데이터" |
| 5 | **AI가 할 일** | 읽기 / 구조화 / 판단 보조 / 보고 / 자동화 | "원장을 읽어 연체 구간별 목록 초안 만들기(구조화·보고)" / "AI가 알아서" |
| 6 | **사람이 할 결정** | 승인 지점 | "선적 보류 여부는 팀장이 목록을 보고 결정" / (빈칸) |
| 7 | **성공 지표** | 전 → 후 | "주 2시간 → 20분, 연체 인지 D+15 → D+3" / "업무가 편해진다" |

!!! warning "5번과 6번이 둘 다 채워져 있나요?"

    AI가 할 일만 있고 **사람의 결정**이 없으면, 그것은 위험한 자동화입니다. 결정과 승인은 사람이 합니다.

## 과업 선정 3기준 {#criteria}

후보 과업이 여러 개라면 각각 세 기준에 **1–5점**을 매기고, 점수마다 **근거 한 줄**을 씁니다. 점수에 정답은 없습니다.

| 기준 | 묻는 것 | 1점 | 5점 |
|---|---|---|---|
| **즉시 효과** | 지금 바로 시간이 줄어드는가? | 효과가 몇 달 뒤 | 다음 주부터 바로 |
| **KPI 직결** | 회사가 이미 재는 숫자와 연결되는가? | 잴 방법이 없다 | DSO·연체율·처리시간 같은 기존 지표가 바로 움직인다 |
| **추가 인프라 불필요** | 새 시스템 없이 지금 도구로 되는가? | 새 시스템·개발·데이터 연동 필요 | 지금 쓰는 AI·엑셀로 된다 |

세 점수가 모두 높은 과업이 **첫 프로젝트 후보**(첫 PoC 후보)입니다. 표를 메모장 · 워드에 옮겨 매깁니다. 예를 들어 '바이어 연차보고서 1차 검토'는 1일차 실습 A-2처럼 지금 도구로 바로 되지만,
'30일 연체 예측'은 데이터 준비와 평가가 더 필요합니다(3일차에서 다룹니다).

## 페르소나 카드 4종 — 내 데이터를 쓸 수 없을 때 {#personas}

회사 데이터를 가져올 수 없거나 내 업무를 밝히기 어렵다면, 가장 가까운 페르소나를 골라 그 사람의 일로 캔버스를 씁니다.
(교육용으로 만든 가상 인물입니다.) 아래 네 명 가운데 한 명을 골라 그 사람의 일로 캔버스를 채웁니다.

=== "페르소나 A 수출 중소 무역사무"

    | 항목 | 내용 |
    |---|---|
    | 누구 | 10~50인 제조사의 무역사무 3년차. AI는 거의 처음(무료 ChatGPT를 가끔) |
    | 하는 일 | 인보이스·선적서류 작성, 입금 확인, 엑셀 미수금 대장 관리 |
    | 불편 | 연체를 늦게 안다 · 영문 독촉 메일이 부담된다 · 결제조건별 위험 차이를 설명하기 어렵다 · 회사 노트북에서 AI가 막혀 있다 |
    | 캔버스 씨앗 | "입금 확인 후 미수금 대장 갱신과 D+7 영문 리마인더 초안 작성" |

=== "페르소나 B 여신·채권 관리"

    | 항목 | 내용 |
    |---|---|
    | 누구 | 중견기업 여신·채권관리 7년차. K-SURE 단기수출보험을 쓰고 ERP를 쓴다 |
    | 하는 일 | 한도 품의, 연체 관리, 보험 사고 통지 |
    | 불편 | 한도 근거가 약해 영업과 갈등 · 만기 후 30일이 넘는 바이어를 손으로 챙긴다 · 같은 보고를 반복한다 |
    | 캔버스 씨앗 | "결제기일이 지난 부보 바이어를 매주 찾아 추가 선적 전 확인 목록 만들기" |

=== "페르소나 C 공공조달 계약"

    | 항목 | 내용 |
    |---|---|
    | 누구 | 글로벌 공공조달 수출기업의 계약·입찰 담당. UN·국제개발은행(MDB)·개도국 정부 입찰 |
    | 하는 일 | 입찰 서류 준비, 입찰·이행·선수금환급 보증서 관리 |
    | 불편 | 보증서 담보 부담 · 부당한 보증 청구 걱정 · 공공 바이어의 지급 지연 · 국가 송금 위험 |
    | 캔버스 씨앗 | "입찰 공고문을 읽고 요건·보증 조건 체크리스트 초안 만들기" |

=== "페르소나 D 재무·기획"

    | 항목 | 내용 |
    |---|---|
    | 누구 | 재무·기획 담당, AI 중급(유료 AI 사용, 엑셀 파워유저) |
    | 하는 일 | 경영진 보고, 사내 AI 도입 기획 |
    | 불편 | 경영진을 설득할 ROI 근거가 없다 · 도구가 난립하고 보안 규정이 걸린다 · PoC를 어떻게 설계할지 모른다 |
    | 캔버스 씨앗 | "월간 미수금·연체 현황 보고서 초안을 AI가 만들고 재무팀이 검증하는 흐름" |

## 옆 사람 검증 질문 {#peer-check}

조별 토론이나 짝과 함께, 옆 사람과 캔버스를 바꿔 보고 **딱 하나**만 묻습니다.

> **"무엇을 놓치면 비싼가?"**


시간이 남으면 이어서 묻습니다.

- 사람이 승인하는 지점은 어디인가?
- 성공을 어떤 숫자로 재나? 지금(전) 그 숫자는 얼마인가?
- 그 데이터는 어디에 있고, AI에 넣어도 되는가(민감도)?
- 새 시스템 없이 다음 주에 시작할 수 있나?

피드백은 **칭찬 → 보완 → 생각 확장** 순서로 짧게 합니다.
예: "불편·위험 칸이 구체적이라 좋습니다 → 성공 지표에 '전' 숫자가 비어 있네요 → 사람 승인 지점을 하나 더 둔다면 어디일까요?"

## 내 프로젝트 데이터 목록 (선택) {#inventory}

무엇이, 어디에, 얼마나 민감한가. 데이터를 가져오는 것이 아니라 **목록만** 적습니다. 개인 도입 기획서 5장(데이터)의 출발점이 됩니다.
발표나 공유 화면에 회사 실명 · 담당자 이름이 보이면 먼저 가립니다.

| 데이터 이름 | 어디에 있나(시스템·파일) | 누가 관리하나 | 민감도(개인정보·거래처 정보·공개) | 갱신 주기 |
|---|---|---|---|---|
| (예) 미수금 원장 | ERP 채권 모듈 → 월말 엑셀 | 재무팀 | 거래처명 포함 — 익명화 필요 | 매일 |
