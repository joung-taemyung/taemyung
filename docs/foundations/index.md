# 기초 지식 F1–F6

코드를 '쓰는' 법이 아니라, **AI가 만든 결과를 실행 · 검증 · 보관 · 공유하는 법**을 비유와 그림으로 풀었습니다. 필요한 일차의 모듈만 골라 읽으면 됩니다. 모든 모듈은 같은 순서입니다 — **비유 → 그림 → 용어 → 실습 어디서 만나나 → 익명 실패 사례 → 완료 체크리스트**.

## 6일을 관통하는 실 {#threads}

같은 주제가 날마다 조금씩 깊어집니다.

| 주제 | 1일차 | 2일차 | 3일차 | 4일차 | 5일차 | 6일차 |
|---|---|---|---|---|---|---|
| 클라이언트·서버·API | 대화창 = 클라이언트, AI 회사 = 서버 | HTTP 요청·응답, API vs 스크래핑 | – | 알림·웹훅 = 서버끼리의 요청 | 요청 1건의 여행(화면 → API → 모델 → DB) | 운영 구조도(SOP 부록) |
| 프로세스·실행 | – | – | 노트북 커널 = 실행 중인 프로세스 | 한 번 / 주기 / 조건 / 상시 실행 | `streamlit run` = 서버 프로세스, 포트, 슬립 | 재시작·모니터링 담당(SOP) |
| 파일·데이터 | CSV · XLSX · UTF-8 | 데이터 사전 · 스키마 · 조인 키 | 노트북 · 모델 파일 | 로그(jsonl) · 리포트 템플릿 · 지표 JSON | 앱 저장소(로그는 CSV로 내려받기) | 솔루션 킷 폴더 구조 |
| 토큰·비용 | 토큰 = 요금 단위 | 뉴스 300건 점수화 비용 | – | 리포트 1회 생성 비용 | 호출 수 × 토큰 × 단가 | 운영비 = 사용자 × 호출 × 일 × 단가 → ROI |
| Git·GitHub | 저장소 · 첫 커밋 · 이력 | 브랜치 · PR · 리뷰 · worktree | 결과 커밋 · PR | 브랜치 · worktree · PR · 자동 이슈 | PR · 리뷰 · 배포 연결 · 팀 저장소 | 팀 저장소 · 릴리스 |
| 재현성 | "사용한 코드와 계산식을 보여 줘" | raw → clean → feature, 규칙 문서 | 시드 · 버전 · 모두 실행 | 기대값 테스트 · 숫자 추적 | `requirements.txt`(배포 재현) | README의 재현 절차 |
| 명세·검증 | 근거 요구 · 인용 확인 · 현안 정의서 | 정제 규칙, 변환 후 검산 | 평가 기준 먼저(봉인 시험셋) | 속성 · 기대값 테스트, 레드팀 | 요구사항 카드 + 인수 기준 → AI 구현 | 측정 계획(KPI 정의) |
| 보안·개인정보 | 데이터 위생 다섯 가지 | 수집의 법·약관, 공개 저장소에 실데이터 금지 | 출력에 데이터 노출 주의 | 로그에 개인정보를 남기지 않기 | Secrets, 프롬프트 인젝션, DRY RUN | AI 사용 규칙서 |

## 각 페이지 읽는 법 {#how-to-read}

모든 모듈은 같은 순서입니다: **비유 → 그림 → 용어 → 오늘 실습 어디서 만나나 → 익명 실패 사례 → 완료 체크리스트**.

- <span class="chip chip--field">[현장 사례 · 익명]</span>은 강사가 참여한 프로젝트의 경험입니다. 회사·기관 이름은 밝히지 않습니다.
- 용어의 자세한 정의는 [용어집](../glossary.md)에 일차별로 있습니다.
