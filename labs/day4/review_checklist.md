# 보고서 사람 검토 체크리스트 12항목 — 확정(서명) 전에 하나씩

AI가 쓴 보고서 초안은 **숫자 대조 · 레드팀 · 이 목록**을 모두 거친 뒤에 사람이 확정합니다. 항목마다 `[x]`로 바꾸고, 못 지킨 항목은 고친 뒤 다시 확인합니다. 보고서 파일 끝(또는 PR 본문)에 붙여 두면 누가 무엇을 확인했는지가 남습니다.

- [ ] 1. **숫자 대조 불일치 0건** — `check_numbers.py`의 결과(`workbench/day4/outputs/number_trace.csv`)에 '값 다름 · 단위 다름 · trace 없음'이 없다. 1건이라도 있으면 발송 중단.
- [ ] 2. **입력에 없는 숫자가 없다** — 문장 속 숫자는 모두 지표 JSON의 어느 칸에서 왔는지 찾을 수 있다(합계 · 비율을 AI가 새로 계산하지 않았다).
- [ ] 3. **가정과 한계를 적었다** — `[가정]` · `[교육용 가정]` 표시가 빠지지 않았고, 모델 한계(합성 데이터 · 가정 값)가 한 줄 이상 있다.
- [ ] 4. **조치는 모두 "권고(사람 승인 전)"** — 한도 변경 · 선적 보류 · 보험 사고발생통지에 승인 주체가 적혀 있고, '했다'고 쓴 문장이 없다.
- [ ] 5. **사고발생통지 기한** — "결제기일부터 1개월 이내"로만 썼고, 통지 여부는 사람(대표 결재)이 정한다고 썼다.
- [ ] 6. **약관의 한정 조항을 일반 규칙처럼 쓰지 않았다** — 특정 조건에서만 쓰이는 비율 · 기한을 모든 거래의 규칙처럼 쓰지 않았다(약관 원문과 대조는 담당 부서).
- [ ] 7. **개인정보가 없다** — 바이어 실명 · 담당자 이름 · 연락처 · 계좌가 없고 `buyer_id`만 쓴다.
- [ ] 8. **상관을 원인처럼 쓰지 않았다** — "A 때문에 B가 늘었다"는 문장은 근거(입력 위치)가 있을 때만.
- [ ] 9. **시나리오는 "가정 시나리오에서의 추정"** — 예측이나 확률처럼 쓰지 않았다.
- [ ] 10. **기준일이 맞다** — 원장 기준일(2026-09-30) · 환율 · 금리의 기준일을 지표 JSON `basis`에 적힌 그대로 썼다.
- [ ] 11. **레드팀 지적을 사람이 가렸다** — 다른 AI의 지적마다 '반영 / 기각'과 이유를 적었다(맞는 것만 반영, 틀린 지적은 기각 — 입력과 규칙을 열어 보고).
- [ ] 12. **요약과 표가 서로 맞고, 초안 표시가 있다** — 요약 3줄의 숫자 = 표의 숫자 · 머리글에 "AI 작성 초안 — 담당자 검토 후 확정".
