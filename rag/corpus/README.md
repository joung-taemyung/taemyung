## 2. 조항 단위로 자르기 (article-aware chunking)

규정 · 약관은 `제N조(제목) → 항(①②) → 호(1. 2.)` 구조입니다. 검색 단위를 **조(條)** 로 맞추면 검색 결과 첫 줄에 조항 번호가 와서 평가(Hit@3 · MRR)를 기록하기 쉽고, 답의 인용도 정확해집니다.

| 설정 | 값 | 이유 |
|---|---|---|
| 자르는 단위 | `제N조(제목)`마다 한 조각. 부칙 · 별표도 각각 한 조각 | 실습 A3의 프롬프트(P5-A2 ①)가 이렇게 시킵니다 — 35조 + 부칙 + 별표 4 = **40조각** |
| PDF에서 지울 것 | 쪽 머리글 · 바닥글(예: "… 여신관리규정 1 / 11") · '제N장' 줄 | 안 지우면 조가 쪽 경계에서 둘로 갈라지거나 머리글이 본문에 섞입니다 |
| 조각 id | `HB-27`(제27조) · `HB-별표1` · `HB-부칙` | 골든셋 · 평가 시트와 같은 형식 |
| 검색 | BM25(rank-bm25), 한국어는 조사가 붙으므로 어절 + 어절 안 글자 2-gram 같은 토큰 방식을 쓴다 | 어떤 방식으로 나눴는지는 계획에서 밝히게 합니다(점수가 여기서 갈립니다) |

- **텍스트판(`.md`)** 은 조 머리가 `## 제N조(제목)` 한 줄이라, PDF에서 글자가 잘 안 뽑힐 때 같은 단계를 거칩니다.
- 앱 ⑥ RAG 페이지는 이 폴더의 `.md`를 같은 규칙(`## 제N조` = 조각 1개)으로 잘라 TF-IDF로 찾습니다. 내 약관 변환본을 화면에서 올리면 그 문서도 같은 방식으로 함께 찾습니다(서버에 저장하지 않음).

## 3. 조항 ID 규칙 (골든셋 · 평가 시트 공통)

| 문서 | 형식 | 예 |
|---|---|---|
| K-SURE 약관 | `KS-조` · `KS-조항호` | `KS-7①2`(제7조 제1항 제2호) · `KS-22의2` |
| 한빛 여신관리규정 | `HB-조` · `HB-조항` · `HB-별표N` | `HB-27②` · `HB-별표1` |
| 법인세법 시행령 | `LAW-CIT-조항호` | `LAW-CIT-19의2①7` |
| 민법 | `CIV-조-호` | `CIV-163-6` |

- 검색 지표(Hit@3 · MRR)는 **조 단위**로 맞춥니다(`HB-27②` → `HB-27`). 답의 정확성(항 · 호까지 맞는지)은 사람이 읽고 확인합니다.
- 오늘 평가에서 정답으로 세는 것은 `gold_ids` 가운데 **`HB-`로 시작하는 것**뿐입니다. 약관(KS-) · 법령(LAW-)에만 정답이 있는 문항은 '코퍼스 밖', 정답이 아예 없는 문항(Q19 · Q20)은 '기권'으로 따로 셉니다 — 규정 PDF에 정답이 있는 문항은 10개입니다.
